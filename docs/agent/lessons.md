# Lessons (orchestrator only; read at session start)

One line each: symptom → cause → guard, at most 250 characters. Keep at most 40 lines: merge lessons or turn them into checks, and prune one when a script, check or skill line guards it. Agents never load this file; a lesson they need goes into their skill or brief as one line.

- A failing test's name was lost → the run was piped through `tail -25` → write long runs to a log file in the scratch folder and read the failures from the file.
- A bench's "after" run reran the "before" binary → cargo in a shared target reuses another worktree's build when your files are older → check the log says `Compiling`, or `touch` the crate sources first.
- Fork CI red on a test the Mac never compiles → a signature change missed a `cfg(not(target_os = "macos"))` caller → after changing a signature, grep its callers inside `cfg(not(...macos))` blocks too.
- Lanes ended their turn while a build ran and stopped → nothing wakes a lane for its own background build → every brief: never end the turn while a build or run you wait on is still going.
- Test copies of the app popped up "A New Build Is Ready" on the user's screen → the update check ran at every start → agent runs use `--control` or `LIGHTCRAFT_NO_UPDATE_CHECK=1`, and headless snapshots for pictures.
- A lane re-downloaded both people-parsing model sets for a test → its test fetched real files into a scratch folder → tests read models from the shared ArtCraft models folder and skip when missing; download tests use a fake server.
- Load reached 100–170 with 6 lanes building → each cargo used all 12 cores → every lane builds with `CARGO_BUILD_JOBS=4`.
- Two lanes measured or tested the other tree's code → worktrees sharing one build folder link each other's crates (cargo keys a crate by its path inside the repo) → one build folder per worktree at a time; after switching trees, touch the sources and check the binary holds your code.
- A merged batch failed the settings-sync test → a lane added `ui.json` keys without deciding sync for them → a new `UiState` field goes into `settings_sync::rules` in the same change.
- A lane spent its round re-timing 3 model sets on 11 photos when the times were already known → briefs asked for broad timing tables → ask for one or two timings only, and start new work (Core ML, a new feature) in a fresh lane, never as a follow-up on a lane with a large context.
- PR bodies and fork notes named the Mac model and the owner's own photos → lanes reported timings with machine details → briefs and reports say "on a test Mac" / "private test photos"; the leak check covers machine details too.
- A script that kept both sides of a conflict in a test file dropped a closing brace; the merge was committed unbuilt → build the touched crate before committing any conflict resolution.
- My briefs for #139/#140 fix rounds, speed, refine and culling sent lanes to the main checkout's build folder despite the 'one build folder per worktree' line → the culling lane's new field broke my merge build twice → briefs name a free target/lane-N per lane; the orchestrator checks in target/review.
- Disk fell to 44 GB free with 7 lane build folders of 60–160 GB each, mostly incremental caches → builds near failure → when free disk < 100 GB, delete debug/incremental in build folders no running rustc uses (pgrep -fl rustc | grep target/...).
- A conflict script that kept both sides of a module list dropped one #[cfg(test)] line → when uniting attribute-led lines, keep each item with its attribute.
- Check scripts written as `(set -e; …) && { push }` pushed a clippy failure → bash ignores `set -e` inside a command that `&&` tests → `set -e` in a subshell didn't stop on a failed cargo here either: chain checks with `&&`, save `$?`, grep the log for `^error|FAILED|panicked`, push only when both are clean.
- PR #170's new ui.json key failed settings_sync after merge → my merge check list for UI PRs missed settings_sync → every ui-egui merge check includes `settings_sync`.
- The batch gate failed a credits test with "no contributors" → target/review held build-script output baked from a removed worktree's path → before a gate in a shared build folder, `touch crates/ui-egui/build.rs` (or any build.rs that reads repo files).
- Six T3 tasks failed at once on "Claude API rate limit reached" → 7 Opus lanes plus Haiku reviews ran together → keep at most 4–5 Opus lanes at a time; resume a stopped lane with a `t3_thread_send` that says to check `git status` and its logs first.
- Lanes spent rounds on repeated timing runs under load → timing is not the goal; algorithm and quality work is → briefs ask for one profile and one before/after CPU number per change, never repeated runs or a quiet-Mac wait.
- Even Tone (PR #228) broke the zoom-window = whole-frame test and was pushed → the lane ran retouch tests only, and `xtask ci --quick` tests changed packages, not their dependents → a retouch change's brief and merge check include `cargo test -p lightcraft-pipeline --lib -- retouch_step tests_retouch tests_window`.
- The Windows check failed on every engine PR for hours, and Fork CI failed twice on `custom`, unnoticed → only local checks were read after merging → after each push to `custom`, read that push's Fork CI result (`gh run list -R techneissa/lightcraft --branch custom`) before the next batch; official workflows the upstream adds start switched on, so switch them off (fork/github-builds.md).
- PR #260 changed the default hair edge and the parse's model tag, and broke a `lightcraft-ui-egui` and a `lightcraft-engine` test it never ran → the lane ran only the modules it touched → a brief that changes a default, a saved tag or a setting names the UI and engine test modules for that setting (`grep -rln <setting or tag> crates/*/src/tests`).
- Lanes spent hours on Fujifilm, Panasonic and DJI raw failures → the user shoots a Sony A7V → raw work on other cameras only when a check of a merge fails, smallest fix, no extra research or upstream follow-up unless asked.
- A lane downloaded a second 1.3 GB copy of the depth model into the assets folder → it didn't know the shared models folder → briefs that need a model name `~/Library/Application Support/ArtCraft/models/<name>/`.
- Each GitHub merge into `custom` started a Fork CI (cancelling the last) and a Fork build (a new update to install) → merge a batch's PRs locally on `custom`, check, push once at the end.
